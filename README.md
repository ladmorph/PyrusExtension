# Pyrus — перенос полей (0.8.4)

Расширение Chrome/Edge Manifest V3. Переносит поля между задачами одного шаблона на одном сервере Pyrus через интерфейс страницы, без API-токена. Задача автоматически не отправляется и не сохраняется.

## Установка и обновление

Откройте chrome://extensions или edge://extensions, включите режим разработчика и выберите «Загрузить распакованное» → папку PyrusExtension. При обновлении файлов нажмите перезагрузку расширения. В версии 0.5.0 старые исходные снимки автоматически сбрасываются: исходную задачу нужно сохранить заново.

## Перенос

1. Откройте исходную задачу с нужными раскрытыми полями → значок расширения → «Сохранить поля этой задачи».
2. Перейдите в целевой черновик того же шаблона → «Сопоставить поля».
3. Проверьте список, выберите поля → «Заполнить выбранные поля».
4. Проверьте значения на странице и сохраните задачу средствами Pyrus.

Исходная задача при копировании не изменяется: считываются только уже открытые поля. В целевом черновике раскрываются группы, из которых скопированы поля. Заполнение идёт в порядке DOM исходной формы сверху вниз, независимо от поиска и порядка выбора. После каждого изменения расширение ждёт обновления DOM, раскрывает появившиеся группы и повторно ищет условные поля. Если поле не появилось, оно пропускается с объяснением. Для появления зависимого поля нужно выбрать и управляющее поле.

Заполненные значения защищены по умолчанию. Для замены включите «Заменять заполненные значения» и повторите сопоставление. При включённой замене исходное пустое значение может очистить целевой текст или снять checkbox. Поиск только скрывает строки списка: выбранные ранее поля остаются выбранными. Кнопки массового выбора действуют на видимые результаты.

## Что изменено по присланному техническому отчёту

Контейнеры Pyrus распознаются по .formFieldBaseWrapper; названия — по .formFieldBaseWrapper__titleWrapper. В ключ сопоставления входит путь родительских групп. Группы раскрываются по .formFieldGroupTitle и признаку .formFieldGroupTitle_expanded. Поисковые поля таблиц, комментарии и вспомогательные textarea копирования исключены.

Поддерживаются обычные input/textarea/select, даты, checkbox (нативное нажатие для срабатывания обработчика), простые редактируемые текстовые блоки Pyrus .multiLineInputContent. Для одиночных списков .formFieldRadio__content поддержан выбор единственного точного совпадения среди role=option в связанном popup. Если вариант не найден или совпадений несколько, выбор отменяется и текст поиска восстанавливается. Очистка непустого списка Pyrus пока не поддерживается.

Множественный выбор, форматированный rich text, файлы, повторяющиеся строки таблиц и поля в iframe пока не поддерживаются. Эти поля отмечаются как неподдерживаемые либо не включаются в снимок. Скрытые и заблокированные поля не читаются, за исключением визуально скрытого input checkbox при видимом контейнере. Совпадение шаблона пользователь проверяет самостоятельно.

Локальные DOM-проверки воспроизводят классы и вложенность из отчёта пользователя. Подписи, данные и обработчики в тестовой форме синтетические. Это не интеграционная проверка на настоящем Pyrus. Сверка значения DOM после записи не подтверждает сохранение на сервере. Нестандартный popup без role=option и особенности реальных обработчиков могут потребовать следующей доработки.

## Диагностика

Если не сработало, откройте «Диагностика и помощь» → «Проверить страницу» → «Скачать отчёт JSON». Укажите тип поля и ожидаемое поведение. Если поля или группы не распознаются, отдельно нажмите «Скачать структуру страницы» в исходной и целевой задачах.

Обычный отчёт содержит версии, время операций, типы и количество элементов, причины пропусков и категории ошибок. Значения, подписи/идентификаторы полей, HTML и URL не включаются. Журнал хранит последние 100 событий в storage.session до завершения сеанса браузера. Технический снимок содержит CSS-классы, имена атрибутов без значений, связи элементов и сведения о доступных iframe; текст, значения, ID и URL не считываются. Снимок скачивается отдельно и не сохраняется в журнале. Файлы автоматически никуда не отправляются.

«Очистить диагностику» удаляет журнал; «Удалить сохранённые поля» удаляет исходный снимок. Исходные значения тоже хранятся только в storage.session.

## Проверка разработки

Браузерное расширение не требует установки npm-зависимостей. Для тестов: установите Node.js и выполните npm install, затем npm test. jsdom используется только тестами. В проверках: обычные поля, защита замены, неоднозначность, условные поля и порядок записи, раскрытие, экспорт без значений, восстановление журнала, классы Pyrus и точный выбор варианта списка.

Справка API: https://developer.chrome.com/docs/extensions/reference/api/scripting


## Справочники и подготовка только черновика (0.7.1)

Копирование исходной задачи больше не вызывает раскрытие, фокус или нажатие полей. Снимок содержит пути групп уже открытых полей. В целевом черновике раскрываются разделы, связанные с переносимыми полями. Сопоставление и заполнение на URL исходной задачи блокируются до раскрытия. Наличие статуса «черновик» программно не проверяется: целевую страницу выбирает пользователь. Старый снимок нужно сохранить заново после обновления.

Одиночный справочник определяется по .formFieldCatalog__content или .formFieldCatalog__mainContent. Расширение открывает поиск, вводит исходное отображаемое значение, ждёт результаты (до примерно 6 секунд) и выбирает единственное точное совпадение среди role=option либо строк связанной таблицы по полному тексту или значению ячейки. Связь popup с полем берётся из aria-owns/aria-controls. Сравнение не удаляет звёздочки или другие знаки из значений. Это выбор настоящей строки через обработчик Pyrus, а не простая вставка текста. После выбора расширение ждёт обновления формы и продолжает сверху вниз.

При неуспехе справочника/списка последующие поля не изменяются. Если управляющий список не выбран для переноса и его значение в черновике отличается, перенос также блокируется с объяснением. При неоднозначном результате расширение не выбирает первую попавшуюся строку. Очистка заполненного справочника, множественные значения, сотрудники и варианты без распознаваемой связи/ролей пока требуют доработки.

Если справочник не сработал, после ошибки нажмите «Скачать структуру ошибки справочника» в диагностике. Снимок раскрытого popup снимается перед закрытием и восстановлением поискового текста. Он содержит только техническую структуру и CSS-классы, без текста и значений. Неудачная попытка сохраняет этот снимок в памяти страницы, он не добавляется в обычный журнал; новая попытка выбора заменяет его. Для выбора другого шаблона сохраните новый источник.


## Запись ручного выбора справочника (0.7.1)

Для разработки реального адаптера нужны связи элементов и последовательность событий, а не сами рабочие значения. В разделе диагностики добавлены «Начать запись справочника», «Завершить и скачать запись», «Остановить и удалить запись».

1. Обновите расширение. На исходной задаче включите запись и закройте окно расширения.
2. Нажмите нужный справочник с уже выбранным значением. Можно открыть список и закрыть его Escape, не меняя источник. Затем откройте расширение и завершите запись. Скачайте файл до перехода на другую страницу.
3. На целевом черновике снова начните запись. Закройте расширение, вручную откройте справочник, найдите то же значение, выберите нужную строку и дождитесь появления зависимых полей.
4. Откройте расширение, завершите запись и скачайте второй JSON. Передайте оба файла, пометив «источник» и «черновик». Если запись не видит событий, приложите техническую структуру страницы и обезличенный скриншот раскрытого списка.

Запись не нажимает, не раскрывает и не заполняет поля: она наблюдает за действиями пользователя на текущей странице. Она переживает закрытие popup расширения, но теряется при обновлении/смене страницы. После завершения снимаются обработчики и MutationObserver. Максимум 40 снимков по 180 элементов; ограничение отмечается в отчёте. CSS-классы и имена атрибутов экспортируются. Текст узлов, value/placeholder, aria-valuetext и значения технических атрибутов заменяются длиной, признаком пустоты и SHA-256 меткой с секретом текущего сеанса, который не включается в отчёт. Строки длиннее 2000 символов не хешируются. При отсутствии WebCrypto поле tokenUnavailable явно указывает невозможность сравнения. Пароли и файловые input исключены из сбора значений. Эти метки позволяют сравнить значение поля с текстом строки/ячейки и понять, как изменилось состояние, без передачи исходных строк. Это диагностические псевдонимы, а не доступ к реестру справочника.

Для сравнения двух записей делайте их в одном сеансе одного браузера: секрет хранится в storage.session расширения. Записи и исходные строки не сохраняются в storage и не передаются на сервер. Скачивание выполняется только кнопкой. Для тестирования можно использовать вымышленные данные. Поддержка самого выбора справочника в 0.6.0 не менялась: эта версия собирает данные для следующего исправления реального виджета.


## Исправление по записи ручного выбора (0.7.1)

В реальном виджете Pyrus aria-owns не разрешается в существующий DOM-элемент, таблица находится в отдельном .inputCompletion__popup, а строки .completionTableMenuItem не имеют role=option. Теперь адаптер использует единственный видимый popup этого типа при фокусе/раскрытии соответствующего input; если видимых popup несколько, выбор отменяется. Строка активируется через события указателя/мыши и click по её ячейке, как при ручном выборе. Обычные варианты .completionMenuItem сопоставляются по .completionMenuItem__name, без добавочных статусов и аватаров.

Помимо полного текста/отдельной ячейки, поддержано отображаемое значение, состоящее из всех видимых непустых ячеек строки в том же порядке с разделителями из пробелов и пунктуации. Дополнительные слова, цифры и перестановка колонок не допускаются. При отсутствии результата полный поисковый запрос последовательно сокращается (часть до разделителя, первые слова), но проверка кандидата всегда выполняется по исходному полному значению. Это не разрешает выбор первого частичного совпадения.

Проверки повторяют признаки из обезличенной записи на синтетической DOM-форме. Настоящий формат отображения многоколоночного справочника нельзя полностью восстановить из хешей: если он отличается от поддержанных вариантов, нужен следующий диагностический отчёт. Записи пользователя не включаются в Git. В этой версии исходная задача по-прежнему только читается.

## Сопоставление заполненной задачи и черновика (0.7.1)

В отчёте версии 0.6.1 перенос останавливался ещё до открытия popup: поле не находилось по строгому ключу либо ранняя проверка возвращала unselected-controller. Это не подтверждённый сбой нажатия по строке справочника — попытки выбора не было.

Теперь берётся чистое название .formFieldTitle__textValue без соседних подсказок и обязательных звёздочек. Сначала сопоставляется полный ключ, затем стабильный fieldId при наличии, затем уникальное название среди совместимых полей. Последний способ допускает различия пути группы и пустого/заполненного виджета. Поля сотрудника и справочника совместимы с универсальным пустым combobox, но не взаимозаменяются между собой при явном типе. Одноимённые конкурирующие поля и разные непустые fieldId не сопоставляются наугад; точные совпадения зарезервированы за своими полями. Проверка после записи заново разрешает соответствие, поскольку после выбора виджет может сменить класс/тип.

Одиночный сотрудник определяется по personFieldAvatar или formFieldInputCompletion__personAvatar и выбирается по единственному точному completionMenuItem__name. Сотрудников с одинаковыми именами расширение не различает и не выбирает первого. Перед копированием источника вручную откройте только нужные разделы: само расширение источник по-прежнему не меняет.

После обновления старый снимок удаляется: обязательно сохраните исходную задачу заново. При совпадающем текущем значении поле не блокируется как заполненное. При отличающемся заполненном значении защита замены по-прежнему действует.

Диагностика сопоставления добавлена в lastPlan и результаты transfer: индекс исходного поля, режим exact-key/field-id/unique-label/missing/ambiguous, типы, число кандидатов и глубина групп. Названия, ID и значения в обычный отчёт не добавляются. Из присланного обезличенного отчёта нельзя установить точное отличие подписей и групп; проверка этой версии в живом Pyrus всё ещё нужна. Регрессионная DOM-проверка воспроизводит цепочку «сотрудник → справочник → зависимый текст» с универсальным пустым combobox и изменением типа после выбора.

## Исправление пустого списка групп (0.7.1)

Отчёт 0.7.0 показал: сотрудник выбирался успешно, но при 34–36 доступных свёрнутых разделах нажатий было ноль. Все исходные поля имели нулевую глубину группы. Пустой массив groupTitles ошибочно трактовался как запрет открывать любую группу. Поэтому следующий справочник оставался недоступным, а остальной перенос блокировался.

Теперь пустые или отсутствующие метаданные групп означают неизвестную структуру: в целевой форме раскрываются все доступные распознанные группы. Начиная с 0.7.2 непустой список также не ограничивает раскрытие. В источнике раскрытие не запускается. При новых копированиях названия уже раскрытых заголовков sourceSections сохраняются отдельно, независимо от восстановления родительских групп у полей. В отчёте раскрытия видны mode (source-groups/all-target-groups) и requestedTitleCount, без названий.

Снимки из 0.7.0 совместимы: повторно копировать источник для этого исправления не требуется. Перезагрузите расширение и повторите сопоставление/перенос в черновике. Наличие статуса «черновик» программно не проверяется; пользователь выбирает целевую страницу. Исправление проверено на DOM-регрессии «пустой список групп → раскрытие → доступный справочник → выбор значения». Оно не доказывает отсутствие других отличий реальной формы.

## Исправление неполного списка групп (0.7.2)

В целевой форме раскрываются все распознанные разделы, включая те, которых нет в списке заголовков источника. Повторное раскрытие после заполнения обнаруживает новые зависимые разделы. Источник остаётся без изменений. Сохранённый снимок версии 0.7.0/0.7.1 совместим, заново копировать его не требуется. Диагностика показывает mode=all-target-groups и реальное число доступных закрытых разделов.

Проверено автоматическими тестами на искусственном DOM, включая структуру соседних групп черновика. Работа на реальном Pyrus пока не подтверждена.

## Выборочное раскрытие и расширенный отчёт (0.7.3)

Отменено массовое раскрытие из 0.7.2. Приоритет имеют пути групп переносимых полей; для старых снимков используются названия открытых разделов источника. Также распознаются скрытые поля, уже присутствующие в DOM: раскрываются их контейнеры. При недостатке метаданных неизвестные разделы остаются закрытыми. Уже открытые пользователем разделы не закрываются. Поддержаны контейнеры .formFieldGroup при чтении путей групп. Старые снимки совместимы, но не содержат новых метаданных.

Проверка пропущенного управляющего поля выполняется только перед следующими за ним полями. Неоднозначный справочник внизу больше не отменяет перенос ФИО вверху.

Отчёт JSON содержит выбранные индексы и настройку замены, сравнение источника и цели перед/после переноса, число скрытых заголовков, кандидатов и их типов, признаки совпадения значений и групп, индекс блокирующего поля, число ненайденных названий групп. Тексты, значения, идентификаторы и ФИО не включаются. После неудачной попытки достаточно нажать «Скачать отчёт JSON». Проверены 37 автоматических тестов на искусственном DOM; реальный Pyrus требует проверки.

## Пропуск отсутствующих полей (0.7.4)

Отсутствующее поле, включая справочник, после ожидания появления получает статус skipped/missing и не блокирует следующие поля. Отсутствующий невыбранный справочник также не блокирует перенос. Порядок источника и ожидание зависимых полей после выбора списка сохраняются. Ошибки выбора существующего справочника и неоднозначность по-прежнему останавливают последующие записи. Проверены 39 тестов, включая отсутствие первого справочника, выбор информационной системы и появление зависимого поля. На реальном Pyrus проверка ещё нужна.

## Задержки и структура таблиц (0.7.5)

Убрана пауза около 600 мс при отсутствии разделов для раскрытия. Совпадающие значения не записываются повторно. Ожидание после изменений и поиска условных полей сохранено. Реальное ускорение требует замера на Pyrus. Технический снимок теперь включает узлы таблиц и ячеек без их текста. Перенос таблиц пока не реализован: требуется структура источника и черновика. Проверены 40 автоматических тестов.

Обычный отчёт JSON объединяет структуру источника (снимается при копировании) и текущего черновика (при экспорте). Для старого снимка sourceMissing=true: чтобы собрать структуру источника, нужно один раз повторить копирование после обновления. Заполнять источник вручную не требуется. Снимки ограничены по размеру, признак truncated указывает усечение. Содержимое ячеек не включается.

## Отдельные структуры сложных полей (0.7.6)

Таблицы .viewTableFieldNew и поля .horizontalMultiInput сохраняются в main.components независимо от общего лимита 140 элементов. Для каждого компонента записывается вложенная структура, до 1200 узлов и 16 уровней, до 30 компонентов каждого типа; усечение отмечается явно. Текст и значения не читаются. Это доработка диагностики: заполнение таблиц и множественных значений ещё не реализовано. Для структуры источника повторите копирование после обновления, затем экспортируйте обычный отчёт из черновика.

## Множественный выбор (0.7.7)

Поля .horizontalMultiInput внутри .formFieldRadio__content копируют выбранные .multiInputToken .token__text как массив. В целевой форме варианты выбираются по одному с точным сопоставлением и проверкой нового токена. Повторный перенос не дублирует значения. Лишние целевые варианты автоматически не удаляются; множественные справочники пока не поддержаны. Для новых значений повторите копирование источника. Проверены 43 теста; реальный Pyrus требует проверки. Таблицы ещё не переносятся: в текущем снимке источника строки отсутствуют в DOM.

## Поиск строк вне знакомого контейнера (0.7.8)

Диагностика tableDiscovery ищет таблицы, строки, ячейки, сетки и canvas во всём документе, включая разметку чтения вне .viewTableFieldNew. Сохраняются связи с предками, соседями и известной таблицей. Ячейки получают приоритет в лимите 600 элементов; усечение отмечается. Глубина отдельных компонентов увеличена до 40. Значения, текст, HTML и идентификаторы не читаются. Для проверки достаточно скачать структуру страницы в источнике, повторный перенос не нужен. Поддержка заполнения таблиц пока не реализована.

## Конфликт открытых списков (0.7.9)

После выбора или ошибки текущему полю отправляется Escape для закрытия списка. Если несколько popup остаются видимыми, используется единственный новый popup, появившийся после открытия текущего поля. При неоднозначности выбор по-прежнему отменяется. Проверены 45 тестов, включая старый popup с таким же значением. Реальный Pyrus требует проверки. Таблицы остаются нерешённой частью: новый глобальный снимок источника содержит заголовки и служебные нижние ячейки, но не строки данных.

## Базовый перенос таблиц (0.8.0)

Таблицы .viewTableFieldNew включаются в снимок и общий порядок заполнения. Идентификация по названию и пути группы, столбцы сопоставляются по заголовкам независимо от порядка. Конкретные названия столбцов не зашиты. Поддержаны текстовые редакторы, одиночные списки, стандартные select и checkbox. Недостающие строки добавляются через .addRowButton. Каждая изменённая ячейка проверяется после записи. Лишние строки не удаляются; неоднозначные или отсутствующие столбцы дают ошибку. Сложные редакторы, множественные справочники в ячейках и большие виртуализированные таблицы требуют отдельной проверки.

При копировании уже открытые таблицы кратко прокручиваются в видимую область, затем исходная прокрутка восстанавливается. Клики, раскрытие разделов и запись значений в источнике не выполняются. Копируются строки, доступные в DOM после отрисовки; пустой снимок таблицы отмечается, а не выдаётся за успешный перенос. Для таблиц необходимо повторить копирование источника после обновления.

Ошибка таблицы не блокирует последующие поля. Возможен частичный перенос таблицы до ошибки; отчёт содержит её причину, размеры, позицию ячейки и количество подтверждённых изменений, без содержимого. Проверены 49 тестов на искусственном DOM; реальный Pyrus пока не подтверждён.

## Заголовки и ограниченные редакторы таблиц (0.8.1)

Для идентификации таблицы сначала читается .formFieldTitle__textValue, затем запасные контейнеры: счётчик строк и подсказки больше не попадают в название при наличии отдельного элемента текста. После обновления повторите копирование источника, чтобы убрать старое название из снимка. Неизвестные редакторы ячеек не обрабатываются как свободный текст. Распознанные списки выбирают существующий вариант через popup с проверкой результата. Ошибка таблицы не блокирует остальные поля.

## Ячейки данных и служебные колонки (0.8.2)

При чтении строк приоритет имеют .viewTableCell и data-col-idx: служебная нумерация не должна увеличивать ширину строки, закреплённая ячейка данных не должна исключаться по классу formCell_sticky. В отчёт добавлены rowWidths для таблиц источника и sourceRowWidths для попытки записи. Несовпадение ширины строки всё ещё останавливает только таблицу. После обновления нужно повторить копирование источника; исправление проверено синтетическими тестами, результат на реальном Pyrus пока не подтверждён.

## Открытие списков внутри таблицы (0.8.3)

Для cellRadioButton__input используется последовательность pointerdown/mousedown/pointerup/mouseup/click. Текст в отображаемый input не записывается: выбирается точный вариант из открытого списка. В диагностике отмечается начало открытия. Повторное копирование снимка 0.8.2 не требуется. Если таблица уже частично заполнена, для её повторного переноса требуется настройка замены заполненных значений. Проверено автоматическим тестом с popup, открывающимся на pointerdown; на реальном Pyrus проверка остаётся необходимой.

## Компактный отчёт и отрисовка строк цели (0.8.4)

Обычный JSON schemaVersion=2 содержит последнюю попытку, ошибки/пропуски и сравнение только проблемных полей. История всех страниц и полные структуры исключены. Для ошибки таблицы сохраняется небольшой локальный контекст до 40 узлов без значений. Полная структура доступна отдельной кнопкой. Перед проверкой и добавлением строк целевая таблица прокручивается в видимую область с ожиданием отрисовки. При table-row-not-added сохраняются этап и число видимых строк. Старый снимок 0.8.2/0.8.3 совместим. Реальная работа требует проверки.
