# Pyrus — перенос полей (0.6.0)

Расширение Chrome/Edge Manifest V3. Переносит поля между задачами одного шаблона на одном сервере Pyrus через интерфейс страницы, без API-токена. Задача автоматически не отправляется и не сохраняется.

## Установка и обновление

Откройте chrome://extensions или edge://extensions, включите режим разработчика и выберите «Загрузить распакованное» → папку PyrusExtension. При обновлении файлов нажмите перезагрузку расширения. В версии 0.5.0 старые исходные снимки автоматически сбрасываются: исходную задачу нужно сохранить заново.

## Перенос

1. Откройте исходную задачу с нужными раскрытыми полями → значок расширения → «Сохранить поля этой задачи».
2. Перейдите в целевой черновик того же шаблона → «Сопоставить поля».
3. Проверьте список, выберите поля → «Заполнить выбранные поля».
4. Проверьте значения на странице и сохраните задачу средствами Pyrus.

Исходная задача при копировании не изменяется: считываются только уже открытые поля. В целевом черновике раскрываются группы, из которых скопированы поля. Заполнение идёт в порядке DOM исходной формы сверху вниз, независимо от поиска и порядка выбора. После каждого изменения расширение ждёт обновления DOM, раскрывает появившиеся группы и повторно ищет условные поля. Если поле не появилось, оно пропускается с объяснением. Для появления зависимого поля нужно выбрать и управляющее поле.

Заполненные значения защищены по умолчанию. Для замены включите «Заменять заполненные значения» и повторите сопоставление. При включённой замене исходное пустое значение может очистить целевой текст или снять checkbox. Поиск только скрывает строки списка: выбранные ранее поля остаются выбранными. Кнопки массового выбора действуют на видимые результаты.

## Что изменено по присланному техническому отчёту

Контейнеры Pyrus распознаются по .formFieldBaseWrapper; названия — по .formFieldBaseWrapper__titleWrapper. В ключ сопоставления входит путь родительских групп. Группы раскрываются по .formFieldGroupTitle и признаку .formFieldGroupTitle_expanded. Поисковые поля таблиц, комментарии и вспомогательные textarea копирования исключены.

Поддерживаются обычные input/textarea/select, даты, checkbox (нативное нажатие для срабатывания обработчика), простые редактируемые текстовые блоки Pyrus .multiLineInputContent. Для одиночных списков .formFieldRadio__content поддержан выбор единственного точного совпадения среди role=option в связанном popup. Если вариант не найден или совпадений несколько, выбор отменяется и текст поиска восстанавливается. Очистка непустого списка Pyrus пока не поддерживается.

Сотрудники, множественный выбор, форматированный rich text, файлы, повторяющиеся строки таблиц и поля в iframe пока не поддерживаются. Эти поля отмечаются как неподдерживаемые либо не включаются в снимок. Скрытые и заблокированные поля не читаются, за исключением визуально скрытого input checkbox при видимом контейнере. Совпадение шаблона пользователь проверяет самостоятельно.

Локальные DOM-проверки воспроизводят классы и вложенность из отчёта пользователя. Подписи, данные и обработчики в тестовой форме синтетические. Это не интеграционная проверка на настоящем Pyrus. Сверка значения DOM после записи не подтверждает сохранение на сервере. Нестандартный popup без role=option и особенности реальных обработчиков могут потребовать следующей доработки.

## Диагностика

Если не сработало, откройте «Диагностика и помощь» → «Проверить страницу» → «Скачать отчёт JSON». Укажите тип поля и ожидаемое поведение. Если поля или группы не распознаются, отдельно нажмите «Скачать структуру страницы» в исходной и целевой задачах.

Обычный отчёт содержит версии, время операций, типы и количество элементов, причины пропусков и категории ошибок. Значения, подписи/идентификаторы полей, HTML и URL не включаются. Журнал хранит последние 100 событий в storage.session до завершения сеанса браузера. Технический снимок содержит CSS-классы, имена атрибутов без значений, связи элементов и сведения о доступных iframe; текст, значения, ID и URL не считываются. Снимок скачивается отдельно и не сохраняется в журнале. Файлы автоматически никуда не отправляются.

«Очистить диагностику» удаляет журнал; «Удалить сохранённые поля» удаляет исходный снимок. Исходные значения тоже хранятся только в storage.session.

## Проверка разработки

Браузерное расширение не требует установки npm-зависимостей. Для тестов: установите Node.js и выполните npm install, затем npm test. jsdom используется только тестами. В проверках: обычные поля, защита замены, неоднозначность, условные поля и порядок записи, раскрытие, экспорт без значений, восстановление журнала, классы Pyrus и точный выбор варианта списка.

Справка API: https://developer.chrome.com/docs/extensions/reference/api/scripting


## Справочники и подготовка только черновика (0.6.0)

Копирование исходной задачи больше не вызывает раскрытие, фокус или нажатие полей. Снимок содержит пути групп уже открытых полей. В целевом черновике раскрываются соответствующие группы. Сопоставление и заполнение на URL исходной задачи блокируются до раскрытия. Наличие статуса «черновик» программно не проверяется: целевую страницу выбирает пользователь. Старый снимок нужно сохранить заново после обновления.

Одиночный справочник определяется по .formFieldCatalog__content или .formFieldCatalog__mainContent. Расширение открывает поиск, вводит исходное отображаемое значение, ждёт результаты (до примерно 6 секунд) и выбирает единственное точное совпадение среди role=option либо строк связанной таблицы по полному тексту или значению ячейки. Связь popup с полем берётся из aria-owns/aria-controls. Сравнение не удаляет звёздочки или другие знаки из значений. Это выбор настоящей строки через обработчик Pyrus, а не простая вставка текста. После выбора расширение ждёт обновления формы и продолжает сверху вниз.

При неуспехе справочника/списка последующие поля не изменяются. Если управляющий список не выбран для переноса и его значение в черновике отличается, перенос также блокируется с объяснением. При неоднозначном результате расширение не выбирает первую попавшуюся строку. Очистка заполненного справочника, множественные значения, сотрудники и варианты без распознаваемой связи/ролей пока требуют доработки.

Если справочник не сработал, после ошибки нажмите «Скачать структуру ошибки справочника» в диагностике. Снимок раскрытого popup снимается перед закрытием и восстановлением поискового текста. Он содержит только техническую структуру и CSS-классы, без текста и значений. Неудачная попытка сохраняет этот снимок в памяти страницы, он не добавляется в обычный журнал; новая попытка выбора заменяет его. Для выбора другого шаблона сохраните новый источник.


## Запись ручного выбора справочника (0.6.0)

Для разработки реального адаптера нужны связи элементов и последовательность событий, а не сами рабочие значения. В разделе диагностики добавлены «Начать запись справочника», «Завершить и скачать запись», «Остановить и удалить запись».

1. Обновите расширение. На исходной задаче включите запись и закройте окно расширения.
2. Нажмите нужный справочник с уже выбранным значением. Можно открыть список и закрыть его Escape, не меняя источник. Затем откройте расширение и завершите запись. Скачайте файл до перехода на другую страницу.
3. На целевом черновике снова начните запись. Закройте расширение, вручную откройте справочник, найдите то же значение, выберите нужную строку и дождитесь появления зависимых полей.
4. Откройте расширение, завершите запись и скачайте второй JSON. Передайте оба файла, пометив «источник» и «черновик». Если запись не видит событий, приложите техническую структуру страницы и обезличенный скриншот раскрытого списка.

Запись не нажимает, не раскрывает и не заполняет поля: она наблюдает за действиями пользователя на текущей странице. Она переживает закрытие popup расширения, но теряется при обновлении/смене страницы. После завершения снимаются обработчики и MutationObserver. Максимум 40 снимков по 180 элементов; ограничение отмечается в отчёте. CSS-классы и имена атрибутов экспортируются. Текст узлов, value/placeholder, aria-valuetext и значения технических атрибутов заменяются длиной, признаком пустоты и SHA-256 меткой с секретом текущего сеанса, который не включается в отчёт. Строки длиннее 2000 символов не хешируются. При отсутствии WebCrypto поле tokenUnavailable явно указывает невозможность сравнения. Пароли и файловые input исключены из сбора значений. Эти метки позволяют сравнить значение поля с текстом строки/ячейки и понять, как изменилось состояние, без передачи исходных строк. Это диагностические псевдонимы, а не доступ к реестру справочника.

Для сравнения двух записей делайте их в одном сеансе одного браузера: секрет хранится в storage.session расширения. Записи и исходные строки не сохраняются в storage и не передаются на сервер. Скачивание выполняется только кнопкой. Для тестирования можно использовать вымышленные данные. Поддержка самого выбора справочника в 0.6.0 не менялась: эта версия собирает данные для следующего исправления реального виджета.
